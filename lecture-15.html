Vibe Coding and AI-Assisted Programming

LLMs as text predictors, effective prompting, code review discipline, ethical implications

§1 · What Is "Vibe Coding"?

Give high-level intent to an LLM (ChatGPT, Copilot, Claude) and receive generated code that you review, test, and iterate. It is not about avoiding programming knowledge—it is about offloading mechanical parts.

Vibe coding (term: Andrej Karpathy, 2025) shifts the engineer's focus from writing every line to designing, reviewing, and validating. The LLM is fast at boilerplate and repetitive structure. You remain responsible for correctness, security, and understanding every line you deploy.

§2 · How LLMs Generate Code

An LLM is a statistical text predictor, not a reasoner. It learned patterns from billions of tokens and generates plausible text—sometimes correct, sometimes confidently wrong.

LLMs have no internal compiler; they never executed the code they learned from. They optimize for looking correct according to training patterns. Common failure modes: hallucinated function names, off-by-one errors, missing NULL checks, undefined behaviour in C/C++. The gap between "looks right" and "is right" is the core challenge.

0

Each token is a word/number/symbol. LLM predicts the next token based on context.
💡 What to notice

The LLM predicts tokens one at a time. After `int max =`, it sees `0` as the most probable next token. But `0` is not always correct—if the array is all-negative, `max` should start as INT_MIN, not 0. The model pattern-matches to training data without reasoning about the logic.

§3 · Effective Prompting

Specificity saves time. Vague prompts get vague code. Include types, algorithm, edge cases, and context.

Bad: "Write a sorting function." Good: "Write a C function `void sort_students(Student *arr, int n)` that sorts an array of Student structs (int id, char name[50], double grade) by grade descending, using insertion sort. Handle n ≤ 1."

The good prompt specifies the exact function signature, struct definition, algorithm, and edge cases. This dramatically reduces the probability of hallucinatory function names or wrong types. When the LLM sees the full context, it generates better code.

§4 · Code Review Discipline

Never paste AI code without reading every line. The model's fluent, well-formatted style is not correlated with correctness.

Classic AI-generated bugs are subtle and easy to miss on a quick read. This is where your knowledge of C/C++ (from L07, L10, and earlier lectures) becomes load-bearing. You are the last line of defense against hallucinations.

💡 What to notice

AI-generated code looks fluent and professional. All the punctuation is correct. But the logic is broken in three ways. This requires reading carefully and testing—not just visual inspection. Code review discipline is not optional when using AI.

§5 · Where AI Tools Excel vs. Fail

AI is good at boilerplate, test cases, and comments. It fails at novel algorithms, security-sensitive code, and C/C++ undefined behaviour.

High reliability: struct definitions, file I/O boilerplate, generating test cases, docstrings, simple translations (Python → C).

Dangerous: novel algorithms not in training data, security code (password readers, crypto), C/C++ undefined behaviour (uninitialized variables, out-of-bounds), subtle concurrency (mutexes, atomics).

A classic example: LLMs still sometimes generate gets(), which is banned in C for 20+ years because it has no bounds checking and guarantees a buffer overflow. The model learned it from old training data and generates it confidently.

§6 · Professional and Ethical Implications

Copyright, academic integrity, and responsibility are not negotiable.

Copyright: LLMs trained on licensed code; AI-generated code's legal status varies. Check company policy before using in commercial products.

Academic integrity: Submitting AI code without disclosure violates most policies. Always ask your instructor.

Responsibility: "The AI wrote it" is not a defence. You own every line you submit or deploy—including its bugs, security holes, and undefined behaviour. The durable skill is knowing what good code looks like, how to debug, and what questions to ask. This does not erode as tools change.
