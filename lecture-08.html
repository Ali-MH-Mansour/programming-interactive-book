§1 · Defining and Calling Functions

A function is a named, reusable block of code. Without functions, you copy logic everywhere you need it — a source of bugs. Functions let you write once and reuse the logic anywhere.

Every function has four parts: a return type (what it sends back), a name, parameters (inputs), and a body (the logic). When the function's definition appears after main, declare a prototype above:

int cube(int n);        // prototype — tells the compiler: there is a function

int main(void) {
    printf("%d\n", cube(4));    // call the function
    return 0;
}

int cube(int n) {               // definition — the actual logic
    return n * n * n;
}

The void keyword means "no parameters" (for main) or "returns nothing" (for functions). A function with no return value doesn't need a return statement — it just ends.

§2 · Parameters, Return Values, and Pass by Value

C copies function arguments into parameters. The original variable is never changed — this is called pass by value. Understanding this prevents a common surprise.

Compare two statements:

int a = 5;
double_it(a);      // pass a to the function
printf("%d\n", a); // still 5 — the original is unchanged

Inside double_it, the parameter x is a separate copy of a. Changing x does not touch a. A function can have multiple parameters, each with its own type:

double power(double base, int exp) {
    double result = 1.0;
    for (int i = 0; i < exp; i++) result *= base;
    return result;
}
Early return: if a function has multiple return points and one is reached, the function exits immediately. The remaining code after that return is skipped.

§3 · Scope and Shadowing

A variable is visible only in the region where it is declared. Local variables live inside one function; global variables live outside all functions and are visible everywhere.

Shadowing happens when a local variable has the same name as a global — the local hides the global inside its function:

int x = 10;        // global

void f(void) {
    int x = 20;    // local — shadows the global
    printf("%d\n", x);  // prints 20
}

int main(void) {
    printf("%d\n", x);  // prints 10
    f();
    printf("%d\n", x);  // still 10
    return 0;
}

Best practice: prefer local variables and function parameters. Globals make code hard to test and reason about.

§4 · The Call Stack and Stack Frames

Every time a function is called, the CPU pushes a stack frame onto the call stack — a block holding that function's parameters and local variables. When the function returns, the frame is popped and its locals disappear.

This stack-based layout is why you get a Segmentation fault if recursion runs infinitely: each nested call pushes a frame until stack memory is exhausted. Watch this animation to see the stack grow and shrink as calls nest:

§5 · Recursion — Functions That Call Themselves

A recursive function calls itself to solve a smaller instance of the same problem. Every recursive function has two mandatory parts: a base case (returns without a self-call) and a recursive case (calls itself with a smaller input).

Factorial is the simplest example:

int factorial(int n) {
    if (n == 0) return 1;         // base case
    return n * factorial(n - 1);  // recursive case — smaller input
}

Trace: factorial(4) → 4 * factorial(3) → 4 * 3 * factorial(2) → 4 * 3 * 2 * factorial(1) → 4 * 3 * 2 * 1 * factorial(0) → 4 * 3 * 2 * 1 * 1 = 24.

Caution: Fibonacci recursion fib(n) = fib(n-1) + fib(n-2) is exponential O(2^n) — for n=40, ~2 billion calls. Use a loop instead.

Factorial recursion — the call stack unwinding

animated
💡 What to notice The recursion dives to the base case factorial(0) = 1, then unwinds back up the call stack, multiplying as it returns. Each level's result depends on the level below it. The deepest nest is factorial(4) → factorial(0) — 5 frames alive simultaneously. Without a base case or without progress toward it, the stack grows forever and crashes.

§6 · Binary Search — Recursion in Action

Binary search halves the search space with each recursive call, giving O(log n) time. The base cases are "not found" (range is empty) and "found" (item at midpoint). The recursive cases recurse on the left or right half.

This example demonstrates why recursion is sometimes the clearest expression of the algorithm:

int binary_search(int arr[], int low, int high, int target) {
    if (low > high) return -1;   // base: not found
    int mid = low + (high - low) / 2;
    if (arr[mid] == target) return mid;  // base: found
    if (arr[mid] < target)
        return binary_search(arr, mid + 1, high, target);  // right half
    return binary_search(arr, low, mid - 1, target);       // left half
}
