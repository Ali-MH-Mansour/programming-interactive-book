Strings

§1 · What Is a String? The Null Terminator

A computer only stores numbers. A string in C is simply a char array whose last element is the null terminator '\0' — the zero byte that marks where the text ends. There is no length stored separately; that one sentinel byte is the whole convention.

Each character is one byte holding its ASCII code — 'H' is 72, 'e' is 101, and so on. The null terminator is stored as 0 (not the digit '0', which is 48). When you write:

char greeting[] = "Hello";   // 5 letters + 1 hidden '\0' = 6 bytes

the compiler lays the six bytes out back to back and appends the terminator for you. Two questions about the same array give different answers, and knowing why is the heart of this chapter:

sizeof(greeting)   // 6 - every byte ALLOCATED, terminator included
strlen(greeting)   // 5 - characters only, counted UP TO the '\0'
The mental model: a C string is a row of boxes with a "STOP" sign at the end. sizeof counts every box that was reserved; strlen walks from the front and stops the instant it reaches the STOP sign — so it never counts the sign itself. Miss the sign entirely and strlen keeps walking into whatever memory follows.

The null terminator — sizeof vs strlen

animated
💡 What to notice strlen walks the boxes left to right and increments its counter for each real character — but the moment it lands on the amber '\0' box it stops and does not count it, ending at 5. sizeof, in contrast, is decided at compile time from the declaration: it reports every byte reserved — all 6, terminator included. That gap of exactly one is the null terminator, and it is why you must always allocate strlen + 1 bytes to hold a string.

§2 · Declaring and Initializing Strings

There are three ways to bring a string into existence, and they are not interchangeable — one of them puts your text in read-only memory, and writing to it crashes the program.

Compare the three styles side by side:

char s1[] = "Hello";      // (a) array, size inferred = 6; MODIFIABLE
char s2[10] = "Hello";    // (b) array, 10 bytes; 4 unused; MODIFIABLE
char *s3 = "Hello";       // (c) pointer to a read-only literal; DO NOT MODIFY
FormWhere the bytes liveCan you change it?
char s1[]on the stack, 6 bytes copied inYes — s1[0]='h' is fine
char s2[10]on the stack, 10 bytes (6–9 zeroed)Yes — room for up to 9 chars
char *s3points into read-only memoryNo — s3[0]='h' is undefined behaviour
The read-only-literal trap. char *s3 = "Hello"; makes s3 point at a constant string literal that the compiler placed in read-only memory. Writing through it — s3[0] = 'h'; — is undefined behaviour, and on most modern systems an immediate crash (SIGSEGV). When you need to modify a string, always use char s1[] or char s2[N].

If you build a string one character at a time, you are responsible for the terminator — without it, the array is just characters, not a string:

char name[6];
name[0] = 'A'; name[1] = 'n'; name[2] = 'd'; name[3] = 'y';
name[4] = '\0';   // REQUIRED - otherwise it is not a string
Forgetting '\0' is one of the most common C bugs. Every string function reads until it finds the terminator. Leave it out and the function marches straight past your data into whatever bytes happen to follow — printing garbage or crashing.

§3 · Reading Strings from the User

Reading text is where beginners first meet the buffer overflow. Two tools do the job — scanf for a single word, fgets for a whole line — and only one of them is safe by default.

scanf("%s", name) reads one word, stopping at the first whitespace. No & is needed — the array name already decays to a pointer (Lecture 6). But by itself it has no length limit: type more characters than the array holds and scanf writes past the end — a buffer overflow. The fix is a width in the format string:

char name[50];
scanf("%s", name);      // DANGER: no limit - long input overflows name
scanf("%49s", name);    // SAFE: at most 49 chars + '\0' = 50 (the array size)

fgets is the safe choice. It reads at most sizeof(name) - 1 characters, always null-terminates, and reads a whole line including spaces. It also captures the trailing newline, which you strip with strcspn:

char name[50];
fgets(name, sizeof(name), stdin);   // length-limited, always terminates
name[strcspn(name, "\n")] = '\0';   // strcspn finds the '\n' index; overwrite it
scanf("%s")fgets
Stops atwhitespacenewline or length limit

Never use gets. It has no length limit whatsoever and was removed from the language in C11. fgets is its safe replacement — there is no situation where gets is the right call.

§4 · Standard String Functions

The workhorses live in <string.h>. Each walks a string until it hits '\0' — which is exactly why every one of them can overflow if the destination is too small. Learn the function and its safe sibling together.

strlen returns the character count, excluding the terminator. It is undefined behaviour on an array that has no '\0':

size_t strlen(const char *s);
strlen("Hello")   // 5
strlen("")        // 0 - the first byte is already '\0'

strcpy / strncpy copy src into dest, terminator included. strcpy checks nothing; the bounded strncpy is safer but has a sharp edge — it may not null-terminate, so you must do it yourself:

char dest[10];
strcpy(dest, "Hello");                // fine here; OVERFLOW if dest too small
strncpy(dest, src, sizeof(dest) - 1); // bounded copy...
dest[sizeof(dest) - 1] = '\0';        // ...strncpy may NOT terminate - do it yourself

strcat / strncat append src to the end of dest. dest must already be a valid string with room for both:

char result[20] = "Hello";
strcat(result, ", world!");                          // "Hello, world!"
strncat(dest, src, sizeof(dest) - strlen(dest) - 1); // bounded append

strcmp compares two strings and returns 0 when they are equal — a return value that trips up nearly everyone:

ReturnMeaning
0strings are equal
< 0s1 comes before s2 alphabetically
> 0s1 comes after s2
Two classic mistakes. (1) if (strcmp(a, b)) is true when the strings are NOT equal (non-zero) — always write if (strcmp(a, b) == 0) for equality. (2) if (a == b) compares the two addresses, never the characters — it is always the wrong way to compare string content.

Two search helpers round out the toolkit — each returns a pointer to the match, or NULL:

strchr(s, 'e')      // pointer to the first 'e' in s, else NULL
strstr(s, "ell")    // pointer to the first "ell" substring, else NULL

§5 · Buffer Overflow and Safe Practices

A buffer overflow is what happens when you write more bytes into an array than it can hold. The excess spills into adjacent memory — corrupting other variables, crashing the program, or opening a security hole. It is the number-one cause of vulnerabilities in C code.

Picture two variables next to each other on the stack — an 8-byte buffer and, right after it, an int. Copying an over-long string into the buffer runs off its end and rewrites the neighbour:

char name[8];
int  secret = 42;                    // lives right after name on the stack
strcpy(name, "AAAAAAAAAAAA");        // 12 A's + '\0' - runs past name[7]
// secret is now overwritten with 'A' bytes - it is no longer 42

Stack corruption — strcpy overrunning a buffer

animated
💡 What to notice The copy fills name[0] through name[7] normally — but it does not stop there, because strcpy has no idea how big name is. It keeps writing, and the next bytes it touches belong to secret. Watch the blue secret cell turn red and its value change from 42 to garbage: nothing warned the program, nothing crashed at the moment of the write. That silent corruption of a different variable is exactly why buffer overflows are so dangerous — and why the bounded functions below exist.
Safe string programming checklist:
  1. Always allocate strlen + 1 bytes — one extra for '\0'.
  2. Use fgets, never gets (or scanf with a width limit).
  3. Use strncpy / strncat instead of strcpy / strcat.
  4. After strncpy, null-terminate manually — it does not guarantee it.
  5. Build formatted strings with snprintf, never sprintf.
char buf[50];
snprintf(buf, sizeof(buf), "Name: %s, Age: %d", name, age);  // respects the size limit

§6 · std::string in C++

C++ offers a better default: std::string manages its own memory. It grows as needed, tracks its own length, and has no null terminator for you to lose and no buffer to overflow.

The same operations that took manual care in C become one-liners:

#include <string>
using namespace std;

string s = "Hello";
s += ", world!";              // concatenation - grows automatically
cout << s << "\n";            // Hello, world!
cout << s.length() << "\n";   // 13  (same as s.size())
OperationWhat it does
s.length() / s.size()number of characters
s.empty()true if length is 0
s.substr(0, 5)"Hello" — the first 5 characters
s.find("world")index of the match, or string::npos
s.c_str()a const char* for C APIs (printf, strcmp)
When to use which. Reach for C strings when interfacing with C libraries, on embedded / memory-constrained targets, or with fixed-length buffers. Reach for std::string for essentially all new C++ text handling — it is safer and shorter. Bridge the two with s.c_str() whenever a C function needs a const char*.
