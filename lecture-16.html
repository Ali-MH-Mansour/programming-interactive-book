§1 · The Preprocessor

The preprocessor runs before the compiler—it is a text-substitution engine that does not understand C.

#include pastes file contents. #define replaces text. #ifdef/#endif conditionally includes code. View the output with gcc -E file.c. Understanding the preprocessor reveals many bugs: macros with missing parentheses, double-inclusion causing redeclaration errors, and conditional compilation that silently excludes code.

§2 · Include Guards and #pragma once

Including a header twice causes redeclaration errors. Guards prevent this.

The pattern: #ifndef HEADER_H, #define HEADER_H, ..., #endif. The first include defines the macro; the second sees the macro already defined and skips the body. Modern shortcut: #pragma once (one line; supported by GCC, Clang, MSVC).

Include Guard Problem & Solution

animated
Without guards, a header included twice causes linker errors
💡 What to notice

Without guards, the struct gets pasted twice into the same translation unit, causing "duplicate type definition" error. With guards, the second inclusion is skipped entirely. Guards are mandatory; forgetting them breaks multi-file projects silently.

§3 · Translation Units and the One Definition Rule

Each .c/.cpp file is a translation unit (TU). A symbol may be declared many times but defined exactly once.

Declaration: extern int counter; — says the symbol exists elsewhere. Definition: int counter = 0; — creates storage. Defining a function in a header included by two .c files violates ODR (One Definition Rule) and causes linker error "multiple definition of `foo`". Put declarations in .h, definitions in .c.

§4 · Header/Source Split

Header (.h): interface (declarations, typedefs, inline functions). Source (.c): implementation (function bodies).

This split enables separate compilation: edit students.c → only recompile students.o. The linker stitches .o files together. Breaking ODR (defining a function in a .h included by two .c files) causes linker errors. Clean separation is the antidote to chaos in multi-file projects.

§5 · Build Systems

Makefiles and CMake automate multi-file compilation. Edits to one file rebuild only affected targets.

Manual (tedious): gcc -c main.c -o main.o, then gcc -c students.c -o students.o, then gcc main.o students.o -o program. Makefile (efficient): declare dependencies (main.c depends on students.h); make only rebuilds dirty targets. CMake (portable): generate Makefiles or IDE projects from a platform-agnostic script.

💡 What to notice

Each .c file compiles independently to a .o object file. Only if a .c changes does its .o rebuild. The linker then combines .o files (a fast operation). On large projects, this incremental rebuild is essential: recompiling only the 3 files you changed, not all 500.

§6 · Internationalization: UTF-8 and Wide Characters

ASCII is 1 byte per character. Unicode (UTF-8) uses 1–4 bytes. Standard functions (strlen, strcpy) count bytes, not characters—be careful.

char = 1 byte, sufficient for ASCII (0–127) but not Unicode. The Cyrillic character "П" is 2 bytes in UTF-8. strlen("Привет") returns 12 (bytes), not 6 (characters). Use wchar_t for wide characters and setlocale(LC_ALL, "") to enable the system locale. UTF-8 is the modern standard for text interchange; Windows traditionally uses UTF-16 (wchar_t), but modern Windows also supports UTF-8 with `chcp 65001`.
