§1 · Sorting and Searching with `qsort` and `bsearch`

The C standard library provides generic sorting and binary search. Both require you to write a comparator function — a higher-order function pattern.

qsort(base, n, size, compare) sorts an array in-place using quicksort. The comparator function compares two elements and returns negative, zero, or positive. Critical: use overflow-safe comparison (a > b) - (a < b) instead of a - b. Once sorted, bsearch(key, base, n, size, compare) finds an element in O(log n) time. Both use void * pointers and require explicit casting inside the comparator.

qsort Comparator and Sorting Steps

qsort uses your comparator to order elements
💡 What to notice

The comparator is called repeatedly: qsort compares pairs of elements to decide their order. Each comparison returns -1 (first < second), 0 (equal), or +1 (first > second). Using (a > b) - (a < b) is safer than a - b because integer overflow is impossible. The same comparator logic works for arrays of integers, structs, or any type.

§2 · Memory Operations: `memcpy`, `memmove`, `memset`

These functions work on raw bytes, not on types. They are fast but demand care with overlap and alignment.

memcpy(dst, src, n) copies n bytes and assumes no overlap. memmove(dst, src, n) handles overlap correctly by choosing the direction (front-to-back or back-to-front). memset(ptr, 0, n) fills n bytes with a value — portable for initializing to zero, but not guaranteed for other types like double. memcmp(a, b, n) compares n bytes lexicographically and returns the sign of the first difference.

⚠️ Zero-initialization note: memset(arr, 0, sizeof(arr)) is safe for integers and pointers but not guaranteed for floating-point. Use calloc instead for portable zero-initialization of doubles.

§3 · Math, Time, and Character Functions

Standard headers <math.h>, <time.h>, and <ctype.h> provide common utilities.

<math.h>: sqrt, pow, fabs, sin, log, etc. Link with -lm on Linux. Note: abs(x) is integer-only; use fabs(x) for doubles.

<time.h>: clock() measures CPU time, time(NULL) gets current Unix timestamp, localtime()` and strftime() format dates.

<ctype.h>: isdigit, isalpha, isupper, tolower, etc. Critical: argument must be `unsigned char` or `EOF` — passing signed `char` > 127 is undefined behavior.

§4 · Safe Type Conversion: `strtol` and `std::stoi`

Never use `atoi` — it silently returns 0 on error. Use `strtol` for detailed error detection or C++ `std::stoi` which throws on failure.

atoi("hello") returns 0 but so does atoi("0") — you cannot tell them apart. strtol provides an end pointer and sets `errno` on overflow, letting you detect all error conditions. C++ safer: std::stoi("42") throws `std::invalid_argument` if conversion fails, and `std::stod for doubles.

strtol vs atoi: Error Detection

animated
atoi silently fails; strtol tells you exactly what went wrong
💡 What to notice

atoi("hello") returns 0 silently — indistinguishable from atoi("0"). strtol("42abc", &end, 10) returns 42 and sets end to point to 'a', so you know where parsing stopped. strtol("99999999999", &end, 10) sets errno=ERANGE to signal overflow. Always check end and errno after strtol for robust input handling.

§5 · C++ Standard Library (STL) Glimpse

C++ offers higher-level abstractions: `vector` (resizable arrays), `algorithm` (sort, find, max_element), and `string` (automatic memory).

std::vector<int> v; grows dynamically — no manual realloc. std::sort(v.begin(), v.end()) sorts in-place (usually introsort, a blend of quicksort and heapsort). std::string manages its own memory — no buffer overflow, no `strlen` to track, automatic concatenation with +=.

These introduce slight runtime overhead (bounds checking, dynamic allocation) but eliminate entire classes of bugs. For performance-critical code, C arrays and manual memory are still used; for correctness, STL is the modern default.
