§1 · Output: printf and Format Specifiers

A format specifier is a contract between you and the runtime. A wrong specifier — %d for a double — is not an error; it is silent garbage.

The call printf(format, arg1, arg2, …) prints its format string verbatim, except that each % conversion consumes one argument, left to right, and formats it. One % per argument.

The general shape of a conversion is %[flags][width][.precision]type. The type letter says how to read the bytes; width is the minimum field width (it pads, never truncates); .precision is the number of digits after the decimal point for %f/%e (default 6) or the maximum characters for %s; the flags - (left-align), 0 (zero-pad) and + (force sign) fine-tune the layout.

TypeSpecifierExampleOutput
int%dprintf("%d", 42)42
long%ldprintf("%ld", 2000000000L)2000000000
double%fprintf("%f", 3.14)3.140000
double (sci.)%eprintf("%e", 3.14)3.140000e+00
double (compact)%gprintf("%g", 3.14)3.14
char%cprintf("%c", 65)A
string%sprintf("%s", "hi")hi
literal %%%printf("100%%")100%
printf("[%8d]",    42);       // [      42]   right-aligned in 8 chars
printf("[%-8d]",   42);       // [42      ]   left-aligned
printf("[%08d]",   42);       // [00000042]   zero-padded
printf("[%+d]",    42);       // [+42]        always show sign
printf("[%8.2f]",  3.14159);  // [    3.14]   width 8, 2 decimals
printf("[%.4f]",   3.14159);  // [3.1416]     4 decimals, no min width
%e and %g: %e is always scientific notation (1.234568e+05); %g picks the shorter of %f/%e and strips trailing zeros. For this course, prefer %f with an explicit precision when you know the magnitude.

Field-Width & Precision Trace — printf("[%8.2f]", 3.14159)

animated
💡 What to notice The .2 precision runs first, rounding 3.14159 to the four characters 3.14. Only then does the 8 width look at the result: four characters in an eight-wide field means four spaces of left-padding (right-alignment is the default). Width never shortens a value — if the number were already wider than 8, all its digits would still print and the field would simply grow. That is why prices formatted with the same %8.2f line their decimal points up in a column.

§2 · Input: scanf and the Address-of Operator

printf needs the value to print; scanf needs the address to write to. That is why every scanf variable gets a &.

&age is the "address-of age" — the slot in memory where scanf will store what it reads. Omit the & and you hand scanf the variable's current (garbage) value and tell it to treat that as an address: undefined behaviour, usually a crash. The one exception is an array name such as char name[50], which is already an address.

The specifiers match printf with one critical asymmetry — the %lf trap. In printf a float is promoted to double, so %f prints both; in scanf there is no promotion, so a double must use %lf (8 bytes) — using %f writes only 4 bytes and corrupts the value silently.

Variable typeprintfscanf
int%d%d
float%f%f
double%f%lf ← different
long%ld%ld
char%c%c
int age;
scanf("%d", age);      // WRONG — garbage value used as an address
scanf("%d", &age);     // CORRECT — &age is the address of the variable

double x;
scanf("%f",  &x);     // WRONG — writes 4 bytes into an 8-byte variable
scanf("%lf", &x);     // CORRECT

// scanf returns the number of items successfully read:
if (scanf("%d %lf", &n, &x) != 2) puts("Bad input");

The Input Buffer & the Newline Trap — reading 42⏎ then a char

animated
💡 What to notice scanf("%d", &n) consumes the digits 4 and 2 and then stops — it leaves the \n the user pressed sitting in the buffer. The next scanf("%c", &c) finds that \n already waiting and reads it instantly, so the user never gets to type. The address-of & is what lets each call write straight into n and c. The fix is one space: scanf(" %c", &c) — a space in a format string skips any leading whitespace, including the stray newline.
The fix, once more: put a space before %c every time you read a character after a number — scanf(" %c", &c). The space skips the buffered \n; %d, %f and %s already skip leading whitespace, which is why only %c is bitten.

§3 · C++ Streams: cout and cin

C++ offers a type-safe alternative to printf/scanf: no format specifiers and no &, because the type is resolved at compile time.

cout << is the "put to" operator and cin >> is the "get from" operator. Both chain — cout << a << " " << b << "\n" — reading left to right. Because n is declared int, cin >> n reads an integer; a mismatched type here is a compile-time error, not the runtime bug a wrong scanf specifier would cause.

#include <iostream>
#include <iomanip>
using namespace std;

int n; double x;
cout << "Enter n: "; cin >> n;          // no &, no specifier
cout << "Enter x: "; cin >> x;

cout << "hello" << endl;               // endl = '\n' + flush the buffer
cout << fixed << setprecision(2) << 3.14159 << "\n";  // 3.14 (persists)
cout << setw(10) << 42 << "\n";        //         42 (next item only)
<iomanip> rules: fixed and setprecision(n) persist for the stream's lifetime; setw(n) applies to the next item only and must be repeated. endl flushes (a syscall per line) — prefer "\n" in loops, endl for interactive prompts.
The buffer trap resurfaces when you mix >> with getline: cin >> n; then cin.ignore(); (discard the leftover \n) then getline(cin, s);. Same principle as the scanf newline trap in §2 — >> read the number and left the terminator behind.

§4 · Reading Characters and Strings

Single characters and whole lines each have a safe idiom — and a classic trap in the functions you should avoid.

Read one character with scanf(" %c", &c) (leading space) or with getchar(). Crucially, getchar() returns int, not char: the sentinel EOF (typically -1) must be distinguishable from every valid character, and on platforms where char is unsigned it cannot hold -1. Store the result in an int before comparing with EOF.

%s reads a single word — it stops at the first whitespace. To read a full line including spaces, use fgets(buffer, sizeof(buffer), stdin), which reads at most size - 1 characters and cannot overflow. Its unsafe predecessor gets was removed from C11 for exactly that reason — never use it.

char c;
scanf(" %c", &c);            // leading space skips whitespace

int ch = getchar();          // returns int so EOF (-1) is representable
if (ch == EOF) { /* input closed */ }

char name[50];
scanf("%s", name);           // no & — an array is already an address; one word
fgets(name, sizeof(name), stdin);  // full line, safe (never use gets)

§5 · Structured Linear Programs: Read → Compute → Write

Every simple program that has no branches or loops yet shares one shape. Making it explicit is the most transferable habit of first-year programming.

Gather all inputs first, derive all results, then print all outputs. Scattering scanf calls between printf calls produces programs that are hard to read and impossible to test; every function you will ever write is a smaller version of this same three-phase shape.

#include <stdio.h>

int main(void) {
    /* READ */
    double celsius;
    printf("Enter temperature in Celsius: ");
    scanf("%lf", &celsius);            // %lf — celsius is a double

    /* COMPUTE */
    double fahrenheit = celsius * 9.0 / 5.0 + 32.0;  // 9.0/5.0, not 9/5 (L03)
    double kelvin     = celsius + 273.15;

    /* WRITE */
    printf("%-12s %12s %12s\n", "Celsius", "Fahrenheit", "Kelvin");
    printf("%-12.2f %12.2f %12.2f\n", celsius, fahrenheit, kelvin);
    return 0;
}
Why it lines up: %-12s left-aligns each header in 12 characters; %12.2f right-aligns each number in 12 characters with 2 decimals, so every decimal point sits under the same column. The structure never changes — reading three values instead of one only changes the count, not the shape.
