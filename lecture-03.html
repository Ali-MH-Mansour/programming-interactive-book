§1 · Integer Arithmetic: Division, Remainder, and Overflow

In C/C++, integer arithmetic is exact — but it truncates rather than rounds, and it wraps silently when a result exceeds the type’s range.

When both operands of / are integers, the result is an integer — the fractional part is discarded (truncated toward zero). So 17 / 5 is 3, not 3.4. The companion operator % gives the remainder after that truncated division: 17 % 5 is 2 because 17 = 3 × 5 + 2.

The sign rule for % (C99/C++11): the result has the same sign as the dividend (the left operand). So -17 % 5 is -2, and 17 % -5 is 2. Remember this whenever you use % with negative values — it is not the mathematical modulo.

Overflow. An int on most modern platforms is 32 bits and holds values in [−2 147 483 648, +2 147 483 647]. Adding 1 to INT_MAX does not produce an error — it wraps silently to INT_MIN (undefined behaviour in C; two’s-complement wrapping in C++20). The cure is to check before you compute, or to use a wider type (long long) or <stdint.h> fixed-width types.

// Integer division and remainder
int a = 17, b = 5;
int q = a / b;   // → 3    (truncated quotient)
int r = a % b;   // → 2    (remainder: 17 = 3×5 + 2)

// Overflow example — wraps to INT_MIN
int x = 2147483647;   // INT_MAX
x = x + 1;           // undefined behaviour (C) / wraps (C++20)

💡 What to notice The quotient is the number of full copies of the divisor that fit into the dividend — any leftover becomes the remainder. The identity quotient × divisor + remainder = dividend always holds (3 × 5 + 2 = 17 ✓). That is how the CPU computes %: it performs the division, multiplies back, and subtracts.

§2 · Floating-Point Numbers: The IEEE-754 Model

Real numbers in a computer are approximations. Every float or double is a finite binary fraction stored in a fixed-width register following the IEEE-754 standard.

A 32-bit float packs three fields into 32 bits:

• Sign (1 bit) — 0 = positive, 1 = negative.
• Exponent (8 bits) — stored with a bias of 127. The actual power-of-two exponent is the stored byte minus 127.
• Mantissa / significand (23 bits) — the fractional binary digits after the implicit leading 1..

Because most decimal fractions cannot be represented exactly in binary (e.g. 0.1), comparing floats with == is dangerous. The safe idiom is fabs(a - b) < epsilon with a suitably small epsilon (commonly 1e-6f for float or 1e-9 for double).

// Never compare floats with ==
float a = 0.1f + 0.2f;
float b = 0.3f;
if (a == b) puts("equal");          // ← WRONG: may not print

// Correct: epsilon comparison
if (fabsf(a - b) < 1e-6f) puts("equal");  // ← correct

💡 What to notice The mantissa stores only the digits after the leading 1. — that leading bit is always 1 for a normalised number, so it is implied and not stored, giving an extra free bit of precision. The exponent field holds 129 (= 2 + 127 bias), not 2. Decoding: value = (−1)⁰ × 2^(129−127) × 1.0111₂ = 1 × 4 × 1.4375 = 5.75 ✓

§3 · Mixed-Type Arithmetic and Explicit Casts

When operands of different types meet in an expression, C/C++ silently promotes the narrower type before computing. Knowing the promotion rules prevents surprising truncation bugs.

Implicit promotion hierarchy (simplified): int → long → long long → float → double. If one operand is double, the other is converted to double before the operation; the result is double.

The classic trap: 1 / 3 is 0 (both operands are int). To get 0.333…, write 1.0 / 3 or (double)1 / 3.

Explicit cast syntax: (target_type) expression. Casts truncate floating-point to integer (toward zero), narrow integers (keeping only the low-order bits), or widen types. Always cast before the operation that needs the wider type, not after.

int   a = 7, b = 2;
double r1 = a / b;           // → 3.0  (int division first, then widens)
double r2 = (double)a / b;   // → 3.5  (a promoted before dividing)
int    n  = (int)3.99;       // → 3    (truncates, not rounds)
Rule of thumb: cast the first operand to the wider type, not the whole result. (double)(a / b) still performs integer division first and yields 3.0, not 3.5.

§4 · Increment and Decrement Operators

The ++ and -- operators are the C family’s shorthand for adding or subtracting 1 — and their prefix vs postfix placement controls when the update happens relative to the surrounding expression.

Prefix (++x): increment first, then use the new value. Postfix (x++): use the current value, then increment. When the operator stands alone on its own statement (e.g. i++;), the choice makes no observable difference — prefer prefix in C++ to avoid a needless copy of user-defined types.

int i = 5;
int a = ++i;   // i becomes 6 first → a = 6, i = 6

int j = 5;
int b = j++;   // b = 5 (old value), then j = 6

// In a for loop — identical effect when the operator is alone:
for (int k = 0; k < 10; k++) { /* ... */ }
for (int k = 0; k < 10; ++k) { /* ... */ }  // ← prefer in C++
Undefined behaviour: modifying a variable more than once without a sequence point — e.g. i = i++ + ++i — is undefined in C and C++. Never do it. Keep each ++/-- on its own statement or in a clearly separated context.

§5 · Mathematical Functions: <math.h> / <cmath>

The standard C math library provides transcendental functions, rounding, and utilities — all operating on double by default, with f-suffix variants for float.

Include <math.h> (C) or <cmath> (C++) and link with -lm on Linux/macOS.

#include <math.h>

sqrt(x)     // √x — always double (sqrtf for float)
pow(x, y)  // xʸ — never use for squaring; write x*x instead
fabs(x)    // |x| for doubles (fabsf for float)
floor(x)   // rounds toward −∞  (3.9→3, −3.1→−4)
ceil(x)    // rounds toward +∞  (3.1→4, −3.9→−3)
round(x)   // rounds to nearest, half away from zero
fmod(x,y)  // floating-point remainder (use instead of % for floats)
Tip: pow(x, 2) is typically computed as exp(2 * log(x)) internally — slower and less accurate than x * x. Always write x * x for squaring.
