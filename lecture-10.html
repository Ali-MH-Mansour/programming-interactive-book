Dynamic Memory Allocation

Allocating memory at runtime from the heap; malloc and calloc; the NULL guard; realloc for resizing; free and memory bugs; C++ new/delete and smart pointers

§1 · Why Dynamic Memory?

Stack arrays require the size to be known at compile time. When size is only known at runtime (after reading a number from the user, or processing a file of unknown length), you must allocate from the heap.

The heap is a large pool of memory that you manage manually with malloc (allocate) and free (deallocate). The payoff: unlimited size, determined at runtime.

§2 · malloc, calloc, and the NULL Guard

malloc(size) allocates uninitialized memory. calloc(count, size) allocates zero-initialized memory. Always check for NULL — allocation can fail if RAM is exhausted.

The NULL guard is mandatory:

int n = 100;
int *arr = malloc(n * sizeof(int));   // allocate 100 ints
if (arr == NULL) {                    // REQUIRED: check for failure
    fprintf(stderr, "Allocation failed\n");
    exit(EXIT_FAILURE);
}
// ... use arr[0..99] ...
free(arr);                            // return memory to heap
arr = NULL;                           // prevent use-after-free
Critical: dereferencing NULL (accessing arr[0] when arr == NULL) crashes the program or corrupts the heap. Never skip the NULL guard.

💡 What to notice malloc returns a pointer to the allocated block. If it returns NULL, the allocation failed and you must exit — never dereference NULL. After free, set the pointer to NULL. This prevents two bugs: if you later accidentally use the pointer, a NULL dereference crashes immediately (clear) instead of silently corrupting memory (subtle).

§3 · realloc — Resizing an Allocation

realloc(ptr, new_size) resizes an existing allocation. If it fails, it returns NULL and leaves the original block valid. Always use a temporary pointer to avoid leaking memory on failure.

Dangerous (causes a leak on failure):

arr = realloc(arr, new_size);  // if realloc fails: arr = NULL, old block lost!

Correct pattern:

int *tmp = realloc(arr, new_size);
if (tmp == NULL) {
    free(arr);                  // free the original block
    exit(EXIT_FAILURE);
}
arr = tmp;                      // update the pointer only after success

§4 · Common Memory Bugs

Three bugs dominate: memory leak (forgetting free), dangling pointer (using after free), and double-free (calling free twice).

This is why you set ptr = NULL after freeing. If you later accidentally call free(ptr) again, free(NULL) is a no-op — safe. And if you accidentally dereference it, NULL dereference crashes immediately instead of silently corrupting the heap.

Growing buffer with realloc

animated
💡 What to notice Each element is stored in the buffer. When the buffer fills up, realloc doubles the capacity. The new buffer may be at a different address — that is why you must update the pointer. Forgetting to free on error leaks memory; dereferencing after free corrupts the heap.

§5 · C++ new, delete, and Smart Pointers

C++ new and delete are type-safe and call constructors/destructors. Smart pointers (unique_ptr, shared_ptr) free automatically when they go out of scope, thanks to RAII.

new behaves like malloc but is type-safe (no cast) and throws an exception on failure instead of returning NULL. Always match new ↔ delete and new[] ↔ `delete[]`:

int *p = new int(42);      // allocate + initialize to 42
int *arr = new int[n];     // allocate n ints

delete p;                  // delete single object
delete[] arr;              // delete array — MUST match new[]

Preferred: smart pointers.** They call destructors automatically when they leave scope:

auto p = std::make_unique<int>(42);  // unique_ptr — one owner, auto-deleted
// p is automatically deleted here when it goes out of scope
