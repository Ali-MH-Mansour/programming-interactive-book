§1 · Why Multithreading?

Modern CPUs have multiple cores. A single-threaded program uses one core — the rest sit idle. Threads let you exploit all cores.

Concurrency means tasks overlap in time (may time-share one core). Parallelism means tasks run simultaneously on different cores. A thread is a lightweight execution unit inside a process. Threads in the same process share memory — a powerful feature, but also a source of bugs.

§2 · Creating Threads with std::thread

C++11 introduced std::thread — the standard portable way to create threads. Each thread runs a function concurrently.

Always call either join() (wait for the thread) or detach() (let it run independently) before the thread object goes out of scope:

#include <thread>

void work(int id) {
    printf("Thread %d working...\n", id);
}

int main() {
    std::thread t1(work, 1);
    std::thread t2(work, 2);

    t1.join();  // main waits for t1
    t2.join();  // main waits for t2
    return 0;
}

§3 · Race Conditions and Data Races

When two threads modify the same variable without synchronization, a race condition occurs. The result is undefined behavior.

A seemingly atomic operation like counter++ is actually three steps: load, add, store. Two threads can interleave these steps and both store the same value — losing increments:

int counter = 0;

void bad() {
    for (int i = 0; i < 1'000'000; i++)
        counter++;  // load, add, store — NOT atomic
}

int main() {
    std::thread t1(bad);
    std::thread t2(bad);
    t1.join(); t2.join();
    printf("counter = %d (expected 2'000'000, got something else)\n", counter);
}

Both threads perform load-add-store. But if thread 2 loads before thread 1 stores, both increment based on the same initial value. The result: counter increments by 1 instead of 2. This is a data race.

§4 · Protecting Shared Data with Mutexes

A mutex (mutual exclusion lock) ensures only one thread accesses a resource at a time. Lock before reading/writing, unlock when done.

Use std::lock_guard for automatic lock/unlock — it locks on construction and unlocks on destruction (RAII pattern):

#include <mutex>

int counter = 0;
std::mutex mtx;

void safe() {
    for (int i = 0; i < 1'000'000; i++) {
        {
            std::lock_guard<std::mutex> lock(mtx);
            counter++;  // now atomic — only one thread at a time
        }  // lock released here
    }
}
Critical: Always hold the lock for the minimum time needed. Holding locks too long reduces parallelism and can cause deadlocks.

§5 · Atomic Operations

For simple operations (like incrementing a counter), std::atomic provides lock-free, hardware-supported synchronization.

std::atomic<int> counter(0); makes counter++ truly atomic — no separate load/add/store steps. Faster than a mutex for simple operations:

#include <atomic>

std::atomic<int> counter(0);

void atomic_increment() {
    for (int i = 0; i < 1'000'000; i++)
        counter++;  // hardware-atomic: single operation
}
