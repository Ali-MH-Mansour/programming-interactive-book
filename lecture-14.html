§1 · The Heterogeneous Computing Landscape

GPUs run thousands of threads in parallel. FPGAs configure custom logic. Each platform trades off power, latency, and development time.

CPUs excel at sequential control flow with few cores (4–64). GPUs pack thousands of cores optimized for data-parallel tasks like matrix multiplication. FPGAs and embedded NPUs (neural processors) shine on edge devices where power and latency are critical. The modern AI engineer must understand when to use each.

§2 · GPU Thread Hierarchy

A GPU organizes parallel threads into a three-level hierarchy: grids, blocks, and warps.

A grid is a collection of blocks. Each block contains up to 1,024 threads and shares fast local memory. Threads within a block can synchronize and share data efficiently. A warp is a group of 32 threads that execute instructions in lockstep; if threads diverge (different control flow), execution serializes. Understanding this hierarchy is essential for writing efficient CUDA kernels.

💡 What to notice

Each thread has a unique (blockIdx, threadIdx) pair. The kernel code is the same for all threads; each thread uses its indices to fetch different data elements. This is SIMD (Single Instruction, Multiple Data) in action.

§3 · CUDA Memory Hierarchy

Memory on a GPU is organized by speed and scope: registers (fastest, private) → shared memory (fast, per-block) → global memory (slow, all threads).

Modern GPUs have limited bandwidth to global memory (a few TB/s). The bottleneck in most kernels is fetching data. The solution: load data into fast shared memory once, then compute using that cached copy many times. This technique—called tiling—is central to high-performance GPU code.

💡 What to notice

Global memory is thousands of times slower than shared memory. By staging data through shared memory, GPUs achieve their advertised parallelism. Without this tiling strategy, global memory bandwidth becomes the bottleneck.

§4 · CUDA Kernel Launch

A CUDA kernel runs as kernel<<<blocks, threads>>>(args). Each thread computes its unique index and processes data.

The syntax add<<<4, 256>>>(d_a, d_b, d_c, N) launches 4 blocks × 256 threads = 1,024 threads total. Each thread computes i = blockIdx.x * blockDim.x + threadIdx.x to get its global index, then processes c[i] = a[i] + b[i]. The CPU enqueues the launch and continues; the GPU executes asynchronously.

§5 · FPGA Basics

An FPGA (Field-Programmable Gate Array) reconfigures its internal logic to implement custom hardware. No CPU overhead, deterministic latency, ultra-low power.

FPGAs shine for edge AI: a smartwatch running a 1 kB quantized model on an FPGA draws milliwatts. GPUs are faster but power-hungry. The trade-off is development time: writing HDL (Verilog) or HLS (C++ with pragmas) takes longer than CUDA. Modern deployment pipelines increasingly target both GPU (cloud inference) and FPGA (edge inference) from the same model.

§6 · Model Optimization for Deployment

Quantization (float32 → int8) and pruning (zero out small weights) reduce model size by 4–10×, enabling deployment on resource-constrained hardware.

Quantization maps floating-point weights to 8-bit integers, shrinking the model 4×. Accuracy typically drops 1–2%. Pruning removes 50–80% of weights (setting small ones to zero), allowing sparse matrix algorithms to skip computation. Knowledge distillation trains a small "student" model to mimic a large "teacher," combining model compression with transfer learning. The standard pipeline: train on GPU (float32) → quantize/prune → export ONNX → deploy to MCU/FPGA/edge NPU.
