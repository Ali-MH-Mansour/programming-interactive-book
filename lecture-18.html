§1 · Complexity — Big-O Notation

Big-O describes how an algorithm's running time grows as the input size n increases, ignoring constant factors and lower-order terms.

The six key classes: O(1) constant time (array indexing), O(log n) logarithmic (binary search), O(n) linear (linear search), O(n log n) linearithmic (merge sort), O(n²) quadratic (bubble sort), and O(2^n) exponential (naïve recursive Fibonacci). For n=10,000: O(log n) ≈ 14 operations; O(n²) = 100,000,000 — a 7-million-fold difference. This is why algorithm choice matters.

§2 · Linked Lists, Stack, and Queue

Three fundamental structures: linked list (pointer-based, O(1) insert at front), stack (LIFO, O(1) push/pop), queue (FIFO, O(1) enqueue/dequeue with circular buffer).

Linked list: Each node holds data and a pointer to the next. Insert at front is O(1); indexing is O(n). Trade: fast insertion for slow random access.

Stack: Last-in-first-out. Use an array with a top pointer. Push and pop are O(1). Applications: function call stack, expression evaluation, undo/redo.

Queue: First-in-first-out. Use a circular buffer with head and tail pointers. Both enqueue and dequeue are O(1) amortized. Applications: task scheduling, breadth-first search, producer–consumer.

§3 · Sorting Algorithms

Five classic sorts, each with different tradeoffs: selection O(n²) always, insertion O(n²) worst/O(n) best, merge O(n log n) always (stable, extra space), quicksort O(n log n) average/O(n²) worst (unstable, in-place), and introSort (hybrid, default in C++ std::sort).

Selection sort: Find the minimum, swap to front, repeat. Always O(n²); not stable (equal elements change order).

Insertion sort: Build a sorted prefix by inserting each new element. O(n) best case (already sorted), O(n²) worst. Stable and fast on small arrays — used inside introsort.

Merge sort: Divide in half, sort halves, merge them. Guaranteed O(n log n), stable, but needs O(n) extra space.

Quicksort: Pick a pivot, partition around it, recurse. Average O(n log n), but O(n²) if pivot is always the smallest (bad input). Unstable, in-place. Used in C's qsort.

Introshift (hybrid): Quicksort with a cutoff to insertion sort on small subarrays + switch to heapsort if recursion runs too deep. Guarantees O(n log n) worst case. Default in C++ std::sort.

§4 · Searching and Hash Tables

Linear search O(n) works on any array. Binary search O(log n) requires a sorted array. Hash tables O(1) average via a hash function and collision resolution.

Linear search: Scan each element. Works on unsorted data.

Binary search: Halve the search space each step. At most log₂(n) comparisons. For n=1,000,000, max 20 comparisons — exponentially faster than linear's 1,000,000.

Hash tables: Compute bucket = hash(key) % TABLE_SIZE. Collisions (two keys hash to the same bucket) are resolved by chaining (each bucket is a linked list) or open addressing (probe for the next empty slot). Load factor (items/buckets) should stay < 0.7; above that, performance degrades.

Merge Sort: Divide, Sort, Merge

animated
Merge sort guarantees O(n log n) by carefully dividing and combining
💡 What to notice

Merge sort splits the array into halves recursively until each part is size 1 (trivially sorted). Then it merges: comparing elements from two sorted subarrays and building a sorted result. The merge step is the heart of the algorithm — two pointers step through the two subarrays, always picking the smaller element next. This divide-and-conquer structure guarantees O(n log n) regardless of input order.

§5 · Course Retrospective

From Lecture 1 (algorithms and C basics) through Lecture 18 (complexity and data structures), you've learned the foundations of programming. Here's the arc.

L01–L03: Fundamentals — what algorithms are, C syntax, operators, types.

L04–L07: I/O and text — formatted input/output, strings, reading from the user and files.

L08–L10: Functions and memory — call stacks, recursion, heap allocation, manual memory management.

L11–L12: Structured and concurrent — structs, multithreading, synchronization primitives (mutexes).

L13–L15: Advanced topics — AI algorithms (linear regression, k-means), GPU programming, vibe coding with LLMs.

L16–L18: Systems and efficiency — preprocessor and build systems, standard libraries, data structures, algorithmic complexity.

The big ideas: correctness first (types, memory safety, testing), then efficiency (algorithms, Big-O, profiling). Never optimize prematurely — profile, identify bottlenecks, then choose the right algorithm or library function. Code is read more than written; clarity and correctness beat cleverness.
