File I/O

Reading and writing files on disk; fopen and fclose; text files with fprintf and fgets; binary files with fread and fwrite; error handling and C++ streams

§1 · Why Files? Opening and Closing

RAM is volatile — all variables vanish when a program exits. Files on disk are persistent. File I/O lets you store results, read configuration, log events, and exchange data between programs.

The C standard library treats files as streams — the same abstraction as printf and scanf. stdout and stdin are just pre-opened streams connected to the terminal. To open a file:

#include <stdio.h>
FILE *fp = fopen("filename.txt", "r");  // "r"=read, "w"=write, "a"=append
if (fp == NULL) {
    perror("fopen");  // print error message
    return 1;
}
// ... read or write ...
fclose(fp);           // ALWAYS close when done

Critical: when you write to a file, C buffers the data in RAM. fclose flushes this buffer to disk. Forgetting fclose can cause data loss — your writes never reach the file. Never forget it, even in error paths.

§2 · Text File I/O — fprintf, fgets, fscanf

fprintf is identical to printf but writes to a file. fgets is the safe way to read lines, and fscanf reads structured data from files.

fgets(buf, n, fp) reads at most n-1 characters, stops at a newline or EOF, and always null-terminates. It is the safe line-reading function — it prevents buffer overflow:

char line[256];
while (fgets(line, sizeof(line), fp) != NULL) {
    printf("%s", line);  // line includes the '\n' from file
}
The feof trap — common mistake: Never test while (!feof(fp)). The feof flag is only set after a read fails, so using it as the loop condition causes one extra off-by-one iteration. Always use the return value of the read function — while (fgets(...) != NULL) — as your condition.

💡 What to notice Each fprintf writes a line to the file. After fclose, the buffer is flushed to disk. Then, fgets reads the file back line by line. The loop continues until fgets returns NULL (end of file). This is the correct pattern: write with fprintf, read with fgets, check the return value.

§3 · Binary File I/O — fread, fwrite, fseek

Binary mode stores exact bytes, no translation. Use fwrite to write raw data and fread to read it back. This is how you store structs and arrays efficiently.

Text mode (the default) performs line-ending translation on Windows — `\r\n` ↔ `\n` — which corrupts binary data. Open binary files with "rb" or "wb":

typedef struct { int id; char name[32]; float gpa; } Student;

Student db[] = {{1, "Alice", 3.9f}, {2, "Bob", 3.4f}};
FILE *fp = fopen("students.bin", "wb");   // binary write
fwrite(db, sizeof(Student), 2, fp);       // write 2 records
fclose(fp);

fp = fopen("students.bin", "rb");         // binary read
Student s;
while (fread(&s, sizeof(Student), 1, fp) == 1) {
    printf("[%d] %s — GPA %.2f\n", s.id, s.name, s.gpa);
}
fclose(fp);
The sizeof idiom: always use sizeof(type), never hardcoded byte counts. If the struct size changes, the code adjusts automatically.

Binary struct packing — Student records

animated
💡 What to notice Each field (id, name, gpa) is stored in its exact byte layout in the binary file. fwrite serializes the struct as-is; fread reads it back byte-for-byte into a new struct. This is much faster than parsing text and guarantees exact reconstruction. Use fseek and ftell for random access — jump to any record without reading the whole file.

§4 · Error Handling — errno, perror, ferror

When a library function fails, it sets errno. Print it immediately with perror — the next call may overwrite it. Always check fopen for NULL and fread/`fwrite` return values for partial I/O.

The standard error-handling pattern:

FILE *fp = fopen(filename, mode);
if (!fp) { perror("fopen"); return 1; }

// ... operations ...

if (ferror(fp)) { perror("I/O error"); }
fclose(fp);

ferror(fp) tests the error flag on the stream. fflush(fp) flushes the write buffer without closing — useful for log files: commit each line to disk before a potentially-crashing next step.

§5 · C++ File Streams — RAII and Safety

C++ streams close automatically when the object is destroyed, thanks to RAII (Resource Acquisition Is Initialization). No forgetting fclose, no manual resource management.

Compare C and C++:

// C — manual, error-prone
FILE *fp = fopen("file.txt", "w");
if (!fp) return 1;
fprintf(fp, "Hello\n");
fclose(fp);  // easy to forget

// C++ — automatic
std::ofstream out("file.txt");
out << "Hello\n";
// out closes automatically when it goes out of scope
Use C FILE * for: C code, performance-critical binary I/O, low-level control. Use C++ streams for: most application code, type safety, exception support, automatic cleanup.
