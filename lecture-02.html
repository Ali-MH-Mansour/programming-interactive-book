What you will learn

Lecture 1 turned source code into a running program. This lecture is about the data that program works on — how a value actually lives in memory, and why the type you write decides what those bits mean.

By the end of this lecture you should be able to:

  • Explain how a value is stored in memory as bits and bytes.
  • Declare and initialize variables of every primitive C type.
  • Use sizeof and <limits.h> to inspect a type's size and range.
  • Apply arithmetic, relational, logical, bitwise, and assignment operators.
  • Predict an expression's value using precedence, associativity, and short-circuit rules.
  • Recognise and avoid the integer-division and = vs == traps.
The key idea: a type is a contract about size and interpretation. Memory stores only bits; the type you declare tells the compiler how many bytes to reserve and how to read them.

§1 · How a value is stored

Memory stores only bits — 0s and 1s. The meaning of a bit pattern comes from its type. The pattern 01000001 is the number 65, the letter 'A', or something else entirely, depending on the type the programmer declared.

The storage hierarchy

UnitWhat it isHolds
bita single 0 or 12 values
byte8 bits28 = 256 distinct values
wordthe CPU's natural unitusually 4 or 8 bytes

Binary is how the machine stores everything. Hexadecimal (base 16) is shorthand: one hex digit = four bits, so one byte = two hex digits.

Decimal 65  =  binary 0100 0001  =  hex 0x41

Watch a single byte being read one bit at a time. Each bit is worth a power of two; where a bit is 1, that power is added to the running total.

Reading one byte: 01000001 → 65 → 'A'

animated
💡 What to notice Every bit position carries a fixed weight — 128, 64, 32, … , 2, 1 — and the value is simply the sum of the weights where the bit is 1. Here only bit 6 (64) and bit 0 (1) are set, so 64 + 1 = 65. Those exact same 8 bits are the letter 'A' when the type is char and the number 65 when the type is int — the bits never changed, only the type that interprets them did.

§2 · Primitive types

Integer types

TypeTypical sizeTypical range (signed)
char1 byte−128 … 127
short2 bytes−32 768 … 32 767
int4 bytes−2 147 483 648 … 2 147 483 647
long4 or 8 bytesplatform-dependent
long long8 bytes±9.2 × 1018

Signed vs unsigned: a signed type (the default) spends one bit recording the sign; an unsigned type (unsigned int, unsigned char, …) has no sign bit, so its range starts at zero and reaches a larger positive maximum.

⚠️ Never assume int is exactly 4 bytes — ask the compiler with sizeof.

A fixed number of bits can only count so far. Step an 8-bit unsigned value up past its maximum and watch what the hardware does when it runs out of room.

unsigned char (8 bits): counting past 255

animated
—
💡 What to notice With 8 bits the largest value is 11111111 = 255. Add one more and every bit flips to 0 — the carry out of the top bit has nowhere to go, so it is simply lost and the value wraps around to 0. This is integer overflow: the count does not stop or error, it silently rolls over like a car odometer. It is exactly why the type's range matters — choose a type too small and a running total can wrap without any warning.

Floating-point types

TypeTypical sizePrecision (approx.)
float4 bytes~7 significant digits
double8 bytes~15 significant digits
⚠️ Floating-point stores an approximation. 0.1 + 0.2 ≠ 0.3. Never compare two floating-point numbers with ==.

char and bool

char c = 'A';
printf("%c %d\n", c, c);    // prints:  A 65
printf("%c\n", 'A' + 1);    // prints:  B

bool (from <stdbool.h> in C): 0 is false, any non-zero is true.

§3 · Sizes and ranges: ask the compiler

Do not guess a type's size — the language gives you two tools to ask directly.

sizeof

#include <stdio.h>

int main(void) {
    printf("int    : %zu bytes\n", sizeof(int));
    printf("double : %zu bytes\n", sizeof(double));
    return 0;
}

Use %zu for a sizeof result.

<limits.h>

#include <limits.h>

printf("%d .. %d\n", INT_MIN, INT_MAX);
printf("%u\n", UINT_MAX);

The integer types are not arbitrary — each is a fixed number of bytes. Reveal them side by side to see how the size grows.

How many bytes each integer type reserves

animated
💡 What to notice Each step up roughly doubles the byte count — 1 → 2 → 4 → 8 — and every extra byte multiplies the number of representable values by 256. That is why char tops out at 255 (unsigned) while a long long reaches past 9 × 1018. A bigger type buys range and precision but costs memory, so you pick the smallest type that safely holds your data — and confirm its size with sizeof rather than assuming.

§4 · Declarations and initialization

A declaration introduces a name and its type; initialization gives it a first value at the same time.

int count = 0;
//  │     │    │
//  │     │    └── initial value
//  │     └────── name
//  └──────────── type
⚠️ A declared-but-uninitialized local variable holds garbage — whatever bits happened to be in that memory. Always initialize: int x = 0;.

const

const double PI = 3.14159;
PI = 3.2;   // COMPILER ERROR

const marks a value that must never change after it is set; any attempt to reassign it is caught at compile time.

§5 · Operators

Arithmetic: + − * / %

printf("%d\n", 7 / 2);      // 3    — integer division TRUNCATES
printf("%f\n", 7.0 / 2);    // 3.5  — floating-point
printf("%d\n", 7 % 2);      // 1    — remainder
Integer division truncates. When both operands are integers, / throws away the fractional part — 7 / 2 is 3, not 3.5. Make one operand a floating-point value (7.0 / 2) to keep the fraction.

Relational and logical

if (x = 3) { ... }   // ⚠️ BUG: ASSIGNS 3 to x — always true
if (x == 3) { ... }  // CORRECT: COMPARES x to 3
⚠️ = assigns, == compares. if (x = 3) is legal C but a logic error — it stores 3 in x and, because 3 is non-zero, the condition is always true.

Bitwise: & | ^ ~ << >>

printf("%d\n", 6 & 3);   // 2   (0110 & 0011 = 0010)
printf("%d\n", 1 << 4);  // 16  (shift left by 4 = multiply by 2^4)

Assignment and compound assignment

x += 5;   // same as  x = x + 5;
x *= 2;   // same as  x = x * 2;
x++;      // increment by 1

§6 · Precedence, associativity, short-circuit

printf("%d\n", 2 + 3 * 4);   // 14 — * binds tighter than +
Engineering rule: when in doubt, use parentheses. 2 + (3 * 4) says exactly what you mean and costs nothing.

Short-circuit evaluation

if (n != 0 && total / n > 5) { ... }   // n != 0 protects the division

If n is 0, the left side is false and total / n is never evaluated — no divide-by-zero. && and || stop as soon as the result is known, which lets the first condition guard the second.

Worked examples

Example 1 — Inspecting a type's size and range

#include <stdio.h>
#include <limits.h>

int main(void) {
    printf("int  : %zu bytes, range %d .. %d\n",
           sizeof(int), INT_MIN, INT_MAX);
    printf("char : %zu byte,  range %d .. %d\n",
           sizeof(char), CHAR_MIN, CHAR_MAX);
    return 0;
}

Example 2 — The integer-division bug and its fix

int a = 7, b = 8, c = 10;
double avg = (a + b + c) / 3;   // BUG: integer division → 8.000000
double avg = (a + b + c) / 3.0; // FIX: floating-point → 8.333333

Example 3 — Evaluating a compound expression

int a = 1, b = 2, c = 3, d = 4, e = 0;
int result = a + b * c > d && !e;
// Trace: b*c=6, a+6=7, !e=1, 7>4=1, 1&&1=1  → result = 1

Chapter summary

  1. Bits, bytes, words — memory stores only bits; the type gives them meaning. The same byte is 65 or 'A' depending on its type.
  2. Primitive types — integer (signed/unsigned), floating-point, char, bool. A fixed size means a fixed range, and overflow wraps around silently.
  3. Sizes and ranges — never assume; use sizeof and <limits.h>.
  4. Declaration and initialization — always initialize; const for values that must not change.
  5. Operators — arithmetic (mind integer division), relational, logical, bitwise, assignment. = assigns, == compares.
  6. Precedence and short-circuit — parenthesise when unsure; &&/|| stop early and can guard the next test.
