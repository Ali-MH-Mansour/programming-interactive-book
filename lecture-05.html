§1 · The if Statement: Choosing a Branch

Selection is the second of the three control structures. Every program is built from just three: sequence (L01–L04), selection (if/switch), and repetition (the loops below).

An if tests a condition and runs its block only when the condition is true. In C/C++ there is no separate boolean type at heart: the condition is any integer expression, and 0 is false while anything non-zero is true. An else gives the alternative path.

Chain the tests with else if for multi-way branching. Conditions are checked top to bottom; the first true branch runs and every other branch is skipped. Order therefore matters — a score of 85 matches >= 80 first and prints "B", even though it also satisfies >= 70.

Always use braces, even for a single statement — omitting them is a classic source of bugs and it is what makes the dangling else below ambiguous.

// Multi-way branching with an else-if chain
if (score >= 90) {
    printf("Grade: A\n");       // first true branch wins
} else if (score >= 80) {
    printf("Grade: B\n");       // 85 stops HERE, never reaches C
} else if (score >= 70) {
    printf("Grade: C\n");
} else {
    printf("Grade: F\n");       // the catch-all
}
The dangling else trap: in C an else always attaches to the nearest preceding unmatched if, regardless of how you indent it. Written without braces, an else you meant for the outer if silently binds to the inner one. The fix is one habit: always brace every if and else body — then the attachment is never in doubt.

§2 · The switch Statement and Fall-Through

A switch branches on the exact value of one integer or character expression. It is faster to read than a long if-chain — but its break-driven fall-through is the single most common beginner bug.

The controlling expression must be an integer or character (no floats, no strings), and each case label must be a compile-time constant. Execution jumps to the matching case and then keeps running downward until it hits a break — so break is required to stop at the end of a case. The optional default catches every value no case matched.

Fall-through is a feature and a trap. Intentional grouping — stacking empty case labels so several values share one body — is the idiomatic use. Forgetting a break is the accidental use, and it silently runs the next case's code too.

// Intentional fall-through: empty labels group values
switch (day) {
    case 1: case 2: case 3: case 4: case 5:
        printf("Weekday\n");   // 1..5 all share this body
        break;
    case 6: case 7:
        printf("Weekend\n");
        break;
    default:
        printf("Invalid day\n");
}
switch vs if: use switch for exact integer/char values (menu choices, day numbers, single-letter grades). Use if/else if for ranges, floating-point tests, or compound conditions — a switch cannot express score >= 80.

Accidental Fall-Through — a missing break (grade = 'A')

💡 What to notice Case 'A' matches and prints "Excellent" — but there is no break after it, so control does not stop. It falls straight through into case 'B' and prints "Good" as well, before the next break finally exits. One grade produced two lines of output. The cure is mechanical: put a break at the end of every case unless you are deliberately grouping labels. Fall-through is legal, so the compiler will not warn you — only the wrong output will.

§3 · The for Loop and the Off-by-One Trap

Use a for loop when you know the count up front. Its header gathers all three pieces of the loop in one place, which is exactly why the boundary is so easy to get wrong by one.

The header is for (initialization; condition; update). The initialization runs once before anything else; the condition is checked before each iteration and the loop exits the moment it is false; the update runs after each iteration. The body therefore runs zero or more times.

The recurring bug is the off-by-one — running the body one time too many or too few. The whole difference is the comparison operator and the bound:

for (int i = 0; i <  10; i++) { }   // 10 iterations: 0,1,...,9   (0-indexed arrays)
for (int i = 1; i <= 10; i++) { }   // 10 iterations: 1,2,...,10  (1-to-n counting)
for (int i = 0; i <= 10; i++) { }   // 11 iterations — usually a BUG
Always ask one question: how many times does this body actually run? For i = 0; i < n the answer is exactly n. Nested loops multiply: an outer loop of 3 around an inner loop of 3 runs the inner body 3 × 3 = 9 times, because the inner loop completes fully for each value of the outer counter.

Loop Trace — for (int i = 0; i < 5; i++) printf("%d ", i);

animated
💡 What to notice The condition i < 5 is tested before every pass, and the body runs only while it is true — so the numbers printed are 0 1 2 3 4, exactly five of them, never 5 itself. The loop ends on the check where i has already become 5: 5 < 5 is false, so the body is skipped and control leaves the loop. Change the operator to i <= 5 and that same final check becomes true — the body runs a sixth time and prints 5. That one character is the off-by-one bug.

§4 · while and do-while: Looping on a Condition

When you do not know the number of iterations in advance, you loop on a condition instead of a count. The only question is whether you test before the body or after it.

A while loop is a pre-test loop: the condition is checked before each iteration, so if it is false at the start the body never runs at all. This is the natural shape for reading input until a sentinel value appears — a special marker such as -1 or 0 that means "stop". A priming read — one input before the loop — gives the first condition something real to test.

A do-while loop is a post-test loop: the body runs first, and the condition is checked after. The body therefore always runs at least once. That is exactly what you want for a menu or for input validation, where you must show the prompt (or read a value) before you can decide whether to repeat.

// while — pre-test, sentinel-controlled with a priming read
int value, sum = 0;
printf("Enter integers (-1 to stop):\n");
scanf("%d", &value);              // priming read: the first value
while (value != -1) {             // tested BEFORE each pass
    sum += value;
    scanf("%d", &value);          // read the next value inside the loop
}

// do-while — post-test, input validation (runs at least once)
int age;
do {
    printf("Enter age (1-120): ");
    scanf("%d", &age);
} while (age < 1 || age > 120);   // keep asking until age is valid
Which loop? Known count → for. Unknown count, test first (may run zero times) → while. Must run the body at least once (menus, validation) → do-while. All three are interchangeable in principle; picking the one that matches the problem makes the code read itself.

§5 · break, continue, and the Everyday Patterns

Two keywords steer a loop from the inside, and a handful of tiny patterns show up in almost every program you will write.

break exits the innermost enclosing loop (or switch) immediately. continue skips the rest of the current iteration and jumps to the next one — in a for loop it jumps to the update first. Both affect only the innermost loop: a break inside two nested loops leaves the inner loop, not the outer.

for (int i = 0; i < 10; i++) {
    if (i == 5) break;        // stop the whole loop → prints 0 1 2 3 4
    printf("%d ", i);
}

for (int i = 0; i < 10; i++) {
    if (i % 2 == 0) continue;  // skip evens → prints 1 3 5 7 9
    printf("%d ", i);
}

The patterns worth memorising:

// Accumulator — collect a running total
int sum = 0;
for (int i = 1; i <= n; i++) sum += i;

// Min / max — initialise from the FIRST element, not from 0
int min = a[0], max = a[0];
for (int i = 1; i < n; i++) {
    if (a[i] < min) min = a[i];
    if (a[i] > max) max = a[i];
}

// Input-validation loop — a do-while that rejects bad input
int x;
do {
    printf("Enter a positive number: ");
    scanf("%d", &x);
} while (x <= 0);
Why min/max starts at a[0]: initialising min = 0 would be wrong for an array of all-positive values (the true minimum is never below 0) and initialising to a huge constant is fragile. The first element is always a real member of the set, so it is the safe starting guess — then compare against the rest.
